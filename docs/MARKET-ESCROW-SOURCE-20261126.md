# 市场订单与托管恢复源码检查点

市场未成交订单、剩余托管余额和待核对标记此前只在内存，重启会丢失。现在下单、取消和撮合均先保存固定操作凭据；正常订单恢复原ID、创建时间、到期时间、成交均价、数量与精确余额，未知结果冻结并保留证据。**71个实际完成套件／1,384项相关测试通过，新增43项**。本轮未启动Minecraft，十阶段尚未全部完成。

## 提交与恢复边界

`resource/market-orders.sqlite` 使用独立SQLite事务、FULL同步、2MiB页缓存和磁盘临时存储。`.authority`保存版本与独立域，数据库绑定贸易域及原生资源域；已有库缺标记、READY缺库、错域、未知版本、事件缺行或当前索引损坏拒绝空重置。INITIALIZING只允许恢复空账本。每次更新比较原完整快照，拒绝旧实例重复取消或撮合。

资产调用前保存RESERVING／CANCELLING；双方MATCHING在同一事务保存。返回false或抛异常不被解释为“未变更资产”。重启只恢复OPEN进入价格簿；其他在途状态保留原凭据并隔离，取消、过期、停服和撮合均不会自动再次操作资产。成交提交后，双方新数量／余额同事务保存；保存失败仍保留MATCHING，已COMMITTED成交不会降成待退款或重放。完成快照必须匹配冻结计划。

原生资源预留、返还、交付和交付补偿改用稳定 `market:<operation>:<step>` 资源事务，精确数量不经过生产加成。外部布尔资源接口保留兼容，但未知结果只隔离。买方按原剩余托管分配成交预留，最后一笔释放小数余量；费用上涨超过预留时不成交。当前可变订单数量被改写时拒绝取消；已有到期时间setter保留。

玩家列表／下单／取消显示待核对和完整ID。管理员或控制台可只读运行 `/resource order review`、`/resource order review <完整UUID>`、`/resource order review after:<上一页末尾UUID>`，每页20条，服务API最多128条。权限为 `starcore.resource.admin`。证据中的余额是原操作前记录，不能单凭该数值断言外部资产现状。尚未提供无证据的解冻／退款命令。
