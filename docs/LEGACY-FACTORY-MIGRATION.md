# 旧工厂审计与显式付费登记

本协议为旧 `factory.*` 元数据提供可复核的登记路径。它不证明旧付款，不猜测原建造人，不执行旧加工任务。旧版 `buildFactory`／`upgradeFactory` 本身是无操作者的模型变更；外部调用方是否曾收费，须另查原始凭据。

## 玩家操作

```
/nationfactory legacy [页码]
/nationfactory registerlegacy <旧工厂ID> <审计摘要> [原请求ID]
/nationfactory operation <请求ID>
/nationfactory show <工厂ID>
/nationfactory enable <工厂ID> <当前版本号> [原请求ID]
```

`legacy` 每页最多8条，仅显示当前创始人本国的原始记录、阻止登记原因、整份旧档摘要和所需新付款。`registerlegacy` 是明确收费操作：从国家库存扣除当前价格版本1的第1级至旧等级L的累计材料，即每项基价 × Σ(k²)，k=1…L。旧字段不提供付款抵扣，也不调用 Vault、玩家钱包或国库。例如3级 SMELTER 一次收取 mineral280、industrial70、energy56；后续升至4级另收320／80／64。

登记保留旧工厂ID、国家、名称、类型和1–10级等级；在当前SQL工厂日志中新增 `REGISTER_LEGACY`，版本从1开始且初始停用。创始人检查后可显式启用，生产仍遵循当前配方和国家／工厂容量限制。登记和普通建造共同计入每国32座上限。

新建筑的 `origin=LEGACY_REGISTERED` 明确区分来源。这个来源下，兼容字段 `builderId` 表示本次付费登记人，`builtAt` 表示登记时间，**均不表示旧建造人／旧建造时间**。原始 `buildTime`、`efficiency`、旧启停状态及全部字段随登记回执保留。旧效率不进入新生产速度；新批次冻结当前配方。普通 `BUILT` 工厂的字段语义及format1编码保持不变。

登记要求受支持的Paper主线程、当前真实国家成员与创始人身份；OP／控制台不具备资产登记特权。Folia写入拒绝。相同请求ID只有原付款人、旧工厂ID和审计摘要全部匹配才只读返回 `ALREADY_APPLIED`，创始人交接后也能核对原请求；新操作仍需当前创始人。同一旧资产改用另一个请求ID返回冲突。`UNKNOWN` 后必须保留原ID核对／重试，不能换ID猜测失败。

## 原始审计与隔离

管理员或控制台可用 `/nationfactory audit` 获取全服摘要和问题计数，需单独权限 `starcore.nationfactory.audit`（默认OP）；该权限只读，不授权登记、修正或补偿。可信原生插件可通过 `legacyAudit()` 获取包含原始字段的不可变报告；`legacyQuotes()`仍要求当前创始人。审计本身不改库存、不推进revision、不重设内存快照基线。

审计直接读取原始属性，不经过旧Factory构造器的等级／效率裁剪、Boolean容错或解析跳过。严格检查规范UUID、名称、类型、毫秒时间、1–10级、0.5–2.0十进制效率、精确true／false、必须字段和未知字段。重复ID（含可解析的非规范别名）全部隔离；有任一recipe／processingStart／processingBatches字段即视作未解决加工，不推断空闲。全局计数错误、缺索引、孤立索引、未知键阻止登记。失效国家在全服审计中标明 `UNKNOWN_NATION`，不得转交其他国家；未来建造时间也不能登记。

摘要算法为 `legacy-factory-audit-v1`：按Java字符串顺序排序全部原始 `factory.*` 属性，连同资源权威域，以长度前缀的UTF-16代码单元序列计算SHA-256。保留原始数值表示、换行和异常Unicode，避免分隔符碰撞或UTF-8替换字符导致的信息损失。单个记录改变、其他旧工厂改变或资源域改变，均须重新取得报价摘要。报告内容随原始条目数增长；不会按不可信声明计数分配巨大列表，旧加载器也已改为遍历实际存在的ID键。

## 提交和来源证明

付款、资源revision、工厂事件和日志头在同一SQL事务／资源写锁中提交。SQL层独立复核：资源域匹配、全量原始字段不变、源记录仍符合登记条件、快照摘要和冻结字段完全相同、ID尚未占用、工厂数量未超限、实际库存扣料正好等于登记价格。不能用未付款快照、旧库存快照或只改回执的方式生成资产。

登记后的原始 `factory.*` 仍完整保留；后续普通保存、升级、启停和生产不删除或归一化旧证据。登记不删除旧副本，也不再次消费；SQL日志中的唯一工厂身份阻止第二次登记。资源保存提交后才发布内存；确认丢失返回UNKNOWN并重读，重读失败则阻止后续资产写入。回滚不留下部分材料变化或半条登记回执。

新来源使用工厂change format2；format1普通工厂的规范字节不变。生产仍使用带工厂绑定的run format2，登记来源额外冻结 `origin=LEGACY_REGISTERED`，SQL验证准入历史时核对该来源。高等级登记可以有较小版本号；普通BUILT仍要求版本不少于等级，不能通过去掉来源标记放宽旧规则。

配套Chronicle只为**之后实际完成的新生产**记录 `production.factory.origin=LEGACY_REGISTERED`。原生产操作者、唯一完成回执和贡献去重不变；普通BUILT／无工厂事件维持原投影。登记、历史等级、启用、升级和旧加工都不会签发个人贡献。发布应使用配套双JAR；旧Chronicle不能接收本来源，回退须恢复匹配的联合备份。

## 尚未解决的旧服情况

加工中、缺字段、未知字段、重复ID、越界值和失效国家继续隔离，不能通过本协议退款、发货、抵扣旧付款或归属未知演员。已有外部付款证据的运营者应先核对，避免将本协议误当成已付款迁移；另需设计能绑定真实凭据的处置协议。当前无自动补偿、旧等级无偿导入、批量管理员代付、实际方块建筑或领地授权。

SQL摘要保障程序内一致性，不提供针对数据库完整改写权限的外部防篡改锚。正常重启、JDBC异常注入和本机MySQL专项不能替代实际Paper调用路径的事务中断、物理断电、远端TLS、长期容量或全栈Folia验收。实际构件和结果见本增量验收报告。
