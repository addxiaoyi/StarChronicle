## 行为变化

广播保留地区人物及以上的资格筛选，按 UUID 稳定排序，`maxReach` 限制本次准入的原玩家数量；0 不通知，负值拒绝。通知回捕获的 Player owner，旧会话失效后不改投重连玩家，不用另一玩家的线程发送消息。人数上限是本地准入上限，不是客户端收到消息的确认。

两种衰减入口统一为 Paper／Folia AsyncScheduler，每 3,600,000 ms 一次；可选 I/O 提交器仍接实际串行写入队列。重复启动幂等，注册失败可重试，停用期间迟到句柄取消，旧周期和排队 I/O 无效，同一 I/O 回调只执行一次，未处理的周期合并为一份待执行工作。显式 `stopDecayTask()` 只停止周期，可再启动；新增默认 `shutdown()` 保持旧接口实现的兼容，原生实现永久拒绝新操作并取消原玩家消息。实际模块先关闭写入队列，再关闭影响力服务。

衰减 UPDATE 增加旧值条件，且必须影响一行才发布新缓存。行被外部修改、删除或写入失败时隔离该玩家，不能把未写入的值当作成功。每个玩家分别提交，不是整批玩家共同事务，也没有新增持久周期 ID 或断电严格一次承诺。既有加分事务没有因此获得多实例协调保证。

直接传入 null 数据库的 API 模式现在可在内存中读写并衰减；这不是恢复失败后的自动降级。加分和传播使用 long 中间计算并限制为合法 int，避免溢出变成负值；本地未公开的来源缓存限制为每人最近 100 项，SQL 原始来源历史完整保留。

## 队列与停用

每个排空任务有独立身份；旧调度完成的迟到错误和重复回调不能取走或失败掉下一批请求。关闭后拒绝新请求，所有排队但尚未开始的请求得到明确异常，捕获的旧排空任务不再执行它们。已准入的单个操作允许完成，服务关闭等待正在持久化的操作离开提交锁；该等待没有硬超时，不认证在线热卸载。

若提交器在执行过程中报告失败，队列停止接收后续工作，避免两个排空任务并发写入。正常单次写入失败仍完成自身异常并继续后续队列；日志异常不阻断普通清理。实际模块的保存失败清理测试同时检查队列已关闭、影响力服务关闭和服务注销。
