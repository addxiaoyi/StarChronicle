## 合并后的协议

- 保留旧 `historyAuthorityDomainId(): Optional<UUID>`、`committedChangesAfter(1..100)` 及原 resource 包回执。上游同名 UUID getter 与 Java 旧签名冲突，改名 `tradeHistoryAuthorityDomainId()`，对应 `tradeChangesAfter(1..128)` 和 model 包回执；上游调用该旧 UUID 描述符的代码必须重编译。三个配套夹具已修正并编译通过。
- 已安装旧日志保留域、序号、随机操作 ID、时间、baseline 与原始编码。新 settlement journal 继承域，仅导入身份快照，包含已清理查询行和精确纳秒；不制造旧 settlement 事件。未来查询行、两种日志、head 和准备 ACK 同事务提交。两边域或身份冲突时拒绝继续，不自动覆盖。
- 新装／上游既有库沿用上游日志；旧 API 以域＋序号派生固定操作 ID，让现有 Chronicle 通用来源读取。两种接口的序号空间不能互换。通用来源沿用历史导入语义，不是科技专用来源的首次只归档协议。
- 旧库对未准备记录保留旧 saveRecord(s) 修订／显式恢复行为；新装／上游库保持严格幂等保存，旧副本不复活已清理查询行。准备过的旧库记录也必须通过持久事务回执，不能直接重写身份。
- 直接／快速交易及撮合先持久准备，成功后绑定原 TransactionFabric 时间线；历史失败只补日志，不重扣钱或重发资源。退款／争议保留原贡献凭据并更新净状态；市场未知结果继续隔离，未撮合托管崩溃恢复与管理员解除尚未完成。
