## 构建与复验

Java 21、Python 3.11+、Node 22 和 Maven Wrapper。Linux 本轮命令：

```bash
# StarChronicle
env MAVEN_OPTS='-Xmx768m -XX:+UseSerialGC' ./mvnw -B -ntp verify
# StarCore：本机依赖缓存齐全，使用离线模式
env MAVEN_OPTS='-Xmx1536m -XX:+UseSerialGC' ./mvnw -o -B -ntp verify
# 首次设备应去掉 -o 下载依赖；离线 verify 的 SBOM 需单独在线生成
./mvnw -B -ntp cyclonedx:makeAggregateBom
```

Windows 使用 `mvnw.cmd` 和 PowerShell 设置 `MAVEN_OPTS`；验收工具自动选择 `java.exe`／`javac.exe`。低内存设备串行运行构建与服务器。

真实客户端与独立运行时：

```bash
npm install --prefix run/epic-client mineflayer@4.39.0
export EPIC_MINEFLAYER_MODULE="$PWD/run/epic-client/node_modules/mineflayer"
python3 tools/prepare-epic-paper.py prepare --route DUNGEON --attempt NEW-ATTEMPT --port 29631   --starcore /path/to/starcore/target/starcore-1.0.0.jar --runtime /path/to/initialized-paper
python3 tools/prepare-epic-paper.py compile --run run/PREPARED-DIRECTORY --java-home /path/to/java21
python3 tools/epic-paper-session.py --run run/PREPARED-DIRECTORY --java-home /path/to/java21 --node /path/to/node --boot 1 --scenario first
python3 tools/epic-paper-session.py --run run/PREPARED-DIRECTORY --java-home /path/to/java21 --node /path/to/node --boot 2 --scenario second
python3 tools/epic-paper-session.py --run run/PREPARED-DIRECTORY --java-home /path/to/java21 --node /path/to/node --boot 3 --scenario third
python3 tools/inspect-epic-paper.py run/PREPARED-DIRECTORY
STARCHRONICLE_EPIC_RUN=run/PREPARED-DIRECTORY python3 -m unittest discover -s tools -p test_epic_acceptance.py -v
```

`--runtime` 指向包含 `paper.jar`、`cache/`、`libraries/` 的初始化 Paper 1.21.11 目录。每条路线独立世界与数据，使用回环地址和空闲端口。对 WAR 使用新 attempt 与端口重复。失败或不完整 boot 不能覆盖后重写成成功；控制器存下 PID、原始日志与退出状态。若测试离线重放旧证据，缺少旧 WAR 保存失败日志时相关负例会明确跳过，必须如实记录。

当前成功目录为 `run/paper-epic-57345b09-{dungeon,war}-linux-policy-1`，端口 29631／29632，六次服务端及客户端均正常退出。独立检查通过、每路线 11 项证据回归通过。旧失败轮次与第一次常规回归的两项失败已归档。[证据包](verification/national-epic-linux-20261125-evidence.zip)含逐文件哈希清单；本机交付物在 `target/national-epic-linux-20261125/`。

归档示例见 `python3 tools/archive-epic-evidence.py --help`。使用唯一 `--label`，用 `--native-reports` 区分专项 XML 与全量 XML，`--full-regression-log` 指向本轮完整日志；`--prior-native-regression` 保留失败日志和 XML。可以用 `--starcore-jar` 固定受验构件，并用 `--native-artifact-commit` 校验生产源码未漂移。
