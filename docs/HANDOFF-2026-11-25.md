## 构建与测试

需要 Java 21、Maven 3.9.x。在两个仓库分别执行，低内存设备不要并行启动 Maven 和验收服。

StarChronicle：

```powershell
$env:MAVEN_OPTS='-Xmx384m -XX:+UseSerialGC'
.\mvnw.cmd -q -DforkCount=0 verify
```

本次结果是 90 个套件、866 项，零失败／错误／跳过。原生 StarCore：

```powershell
$env:MAVEN_OPTS='-Xmx320m -Xss1m -XX:+UseSerialGC -XX:ActiveProcessorCount=1 -XX:TieredStopAtLevel=1 -XX:ReservedCodeCacheSize=48m -XX:CompressedClassSpaceSize=64m'
mvn -q -DforkCount=0 '-Dspotless.skip=true' '-Dtest=QuestEvidenceServiceTest,DungeonRepositoryEpicReceiptTest,DungeonRepositoryIdempotencyTest,NationFoundingOperationTest,WarDeclarationOperationRestartIntegrationTest,WarCompletionReceiptTest,WarMenuReinforcementOwnerTest' test
mvn -q -DskipTests '-Dspotless.skip=true' package
```

本次上述原生 59 项全部通过，随后打包成功。未跑本轮原生完整回归；历史全量回归曾失败。`forkCount=0` 没有产生新的覆盖率结论。两份 JAR 的精确 SHA-256 在 [测试报告](NATIONAL-EPIC-TEST-REPORT.md)。

## 新设备最先做的事

先完成阶段 1 的最终验收，保留失败证据，再推进其他阶段。不要从默认《帝国最后的继承人》的剧情选项推断已经真实扣款或结束战争；使用可选 `last-heir-strategy/1`。

1. 获取两个分支并构建；阅读 [国家史诗契约](NATIONAL-EPIC-CONTRACT.md) 和 [操作示例](../examples/national-epic/last-heir-strategy/README.md)。
2. 准备 Paper 1.21.11 的独立测试运行时。`prepare-epic-paper.py --runtime` 需要包含 `paper.jar`、`cache/`、`libraries/` 的已初始化目录，同盘硬链接缓存以节省空间。保留单独世界和插件数据，使用回环地址及独立端口。
3. 安装 Python 3.11+ 与支持该客户端的 Node.js。真实客户端使用 `mineflayer@4.39.0`；在主仓库执行以下设置，无需改写旧机器绝对路径：

```powershell
npm install --prefix run/epic-client mineflayer@4.39.0
$env:EPIC_MINEFLAYER_MODULE=(Resolve-Path run/epic-client/node_modules/mineflayer).Path
```

4. 用 `python tools/prepare-epic-paper.py --help` 创建并编译新目录。传入 `--route DUNGEON`、新的 `--attempt`、两份新 JAR、实际 `--runtime` 和 `--java-home`。然后用 `epic-paper-session.py --run ... --java-home ... --node ... --boot 1` 启动，在控制器输入 `scenario first`；完成后分别以 boot 2 / 3 输入 `scenario second` / `scenario third`。
5. 在独立目录对 `--route WAR` 重复上述流程，执行 `inspect-epic-paper.py`，再运行 `archive-epic-evidence.py`。检查器目前尚未对完整成功轮次实测，应核对其输入和断言，不能只凭脚本存在宣布通过。
