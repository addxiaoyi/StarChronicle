# 玩家直售只读审计

`/trade audit <完整交易ID>`和`PlayerTradeRecoveryService.audit(actor, offerId)`提供原交易双方可查询的核对材料。当前国家成员、继任创始人或管理员身份不会替代原买方／原卖方身份；原参与者离国后仍可查询。

审计在同一个SQL读事务中校验资源权威、整个玩家交易日志的连续序列／每单版本／冻结条款／累计SHA，以及已结算交易的精确国库税款回执。它返回日志权威域、已提交末尾序号与摘要、目标交易的完整步骤。单笔目前最多9步。其他交易的正文不会出现在结果中；整个日志的末尾可能晚于目标交易的最后一步。

查询不调用钱包，也不查询当前余额、补历史、重试付款、退款、释放库存或推进任何交易状态。钱包或国家服务暂不可用不影响读取既有SQL证据；SQL损坏／不可用时整次查询失败，不返回部分“已核验”结果，也不回退到旧文件。生产存储路由已转发该能力。

## 付款证据

每笔返回三个预定步骤：买方扣款（货款＋费用）、卖方收款（货款）、买方退款（原扣款总额）。金额、账户、方向和提供者都来自原冻结条款，结果来自该步骤后紧邻的持久记录。

| 证据 | 实际含义 |
| --- | --- |
| `NO_INTENT` | 本地尚无该步骤的调用意图；不表示需要执行该步骤。正常成交也不会执行退款。 |
| `INTENT_WITHOUT_RESULT` | 意图已提交，结果未记录。调用可能尚未发生，也可能已经成功；不能据此重新调用。 |
| `PROVIDER_ACKNOWLEDGED` | 提供者返回成功，且本地保存了响应。不是提供者磁盘持久付款凭证。 |
| `PROVIDER_REJECTED` | 提供者明确拒绝，且本地保存了响应。依原状态机决定后续补偿。 |
| `UNKNOWN` | 本地已保存调用结果不明确的记录；保持人工核对状态。 |

API中的步骤序号和摘要标识本地日志记录，不是已传入Vault的幂等键或外部交易ID。摘要没有独立外部防篡改锚；数据库与日志头同时被恶意重写不在本地完整性校验保证之内。

## 后续处理

未接受报价仍由原卖方决定。已知安全中间状态提示原卖方使用原ID继续，执行时仍会重新核验权威域及原状态；查询本身不推进。`SETTLED`的历史投影待办也仅提示可继续。已关闭交易无需继续。

任何未完成INTENT、UNKNOWN或退款拒绝都提示需要原钱包提供者的独立付款证据，保持当前义务与库存托管。当前Vault／Essentials组合没有按原调用ID查询持久付款回执的能力。本版没有提交管理员猜测、按余额或超时强制结算、强制退款或解除UNKNOWN的入口。

若后续接入具有可查询幂等回执的钱包，仍必须建立权威域、原调用ID、账户／方向／金额／终态的完整绑定以及持久审计协议；余额、后台截图和管理员声明不能替代这一合同。

## 本轮范围

新增只读审计，不改变直接交易的付款、库存、税费或Chronicle贡献协议；正常成交贡献仍只来自`SETTLED`。完整付款合同见[玩家直售恢复](PLAYER-TRADE-RECOVERY.md)。市场订单簿、快捷买卖、其他钱包入口、永久UNKNOWN处置和长期日志容量仍待推进。当前查询仍核对全量日志，不能把单笔返回有界当作已经完成容量优化。

实际构件、SQLite／MySQL测试、Paper真实调用中断与保留失败见[审计验收报告](PLAYER-TRADE-AUDIT-TEST-REPORT.md)。
