## 已实现的源码行为

- 升级检查与扣材在原玩家的实体 owner 中连续执行，提交前复核当前仓库和管理权限。停用、重连、退出、实体退休、被拒绝的任务以及旧回调不能读取另一个玩家或继续收费；共享仓库升级按服务和仓库实例串行。
- 延迟完成使用全局调度句柄，持有精确令牌和服务代际。替换、停用和迟到句柄被隔离；一个取消失败不会阻止其他句柄或玩家 future 清理。周期保存使用 Paper/Folia 通用异步调度，只处理脱离玩家／世界的仓库状态，同时最多一个保存 future 未完成。
- 升级与退款合入版本 2 的 `warehouse_active_upgrades.json` 原子快照；旧无版本升级及独立退款文件仍可读取。旧退款文件原样保留；版本 2 只读统一权威，不重新导入已发放旧退款。坏文件、缺字段、未知版本、重复记录、坏数量／材质、只有临时文件时拒绝恢复，停用不能覆盖原证据。
- 新写入者使用文件锁、加载时 SHA-256 和每次提交变化的 revision，拒绝陈旧实例。临时文件 force 后原子替换，没有非原子写回退；无法确认保存时冻结该升级服务后续业务。
- 扣材前保存目标等级、配方成本及原背包完整物品字节，先把消费标为结果不明。背包 setter 抛错后只接受同一原玩家背包中完全未变或完全符合计划的结果；不完整／不可读结果保留凭据，拒绝自动重试和取消退款。明确金币拒绝时按原堆叠恢复，保留原物品元数据。
- 完成之前保存完成声明，仓库目标等级持久化之后才清除升级证据。恢复看到已达目标等级不会再升一级；完成声明后的记录不能被取消生成退款。重载、仓库变更、最终保存与证据退休共享同一写锁，保存时不持仓库监视器，避免与快照序列化互锁。
- 付费加速先保存不明付款声明，确认扣款后保存已付金额；保存仓库失败后独立重开可继续完成，不再收第二次加速费用。无法判定的加速扣款继续隔离。
- 退款领取回原玩家 owner，领取前先保存不明声明；背包或余额结果不明时重启仍不自动再次发放。背包放不下的材料仍记为待领，不落地生成物品。取消和退款状态在同一个快照中提交。
- 国家仓库材料 API 在同一当前仓库锁内整批预检；缺少任一材料、无效／负数量或仓库不存在均失败。按实际原槽位扣除，修复 `withAmount` 仅创建副本却未写回造成的部分材料漏扣。普通存入日志也移到保存请求之前。

## 仍需验收的边界

仓库文件、升级记录、内部经济与 Minecraft 玩家存档没有共同持久事务；进程崩溃或主机断电时不宣称严格一次。未知结果保留以供只读核对，没有自动核销或盲目重放。原始物品 bytes 的单测使用 API 形状值夹具，没有真实 NBT／PDC 服务端解码证明。旧版本不遵守文件锁与版本协议，仍不认证降级；旧记录已缺失的物品元数据无法重建。

大仓库快照仍会完整序列化，升级提交及原子文件写入可能占用玩家 owner 时间；启动和长期容量需继续评估。默认取消仍按原配方退一半材料及扣除时间费用后的余额，不把此规则描述为完整原物品退回。当前构件真实多人、物品／退款、重启恢复、第三方组合、全栈 Folia 与长期负载继续需要实服验收。
