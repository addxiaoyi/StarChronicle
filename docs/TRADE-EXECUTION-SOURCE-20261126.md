# 国家贸易持久执行与恢复

2026-11-26 源码检查点。原生国家贸易先前每次生成新随机编号，以 consume／grant 分步交付，再用布尔结果尝试补偿。保存后回包丢失可能无法判断是否应退款，配额预留和路线累计也没有与执行进度一起保存。

现在每笔执行冻结条款、双方国家、资源／国库存储域及独立执行编号。玩家发起仅保存自己一方的确认；另一方当前创始人确认后，才在同次资源保存中建立 PREPARED 与全部匹配的配额预留。付款、原子双库存交付和退款各自使用固定编号、严格匹配原回执。PAID 或 REFUND_PENDING 可跨重启续办；无法确定提交、回执冲突或存储域变化时保留原编号，不立即退款。资源检查点保存异常后重读完整耦合快照；读不回或校验失败则隔离。

完成记录和路线累计量一起持久化。退款确认后才释放原窗口配额，不能减少新周期用量。每分钟按编号轮转最多恢复 32 笔，持续失败不会永久挡住后续记录，也不会替玩家批准提案。原生直接 useQuota 也新增同步保存和异常对账，避免使用量仅在内存中，随后重启丢失。

公开入口为 `/resource trade agreements execute <协定ID> <执行编号>` 与 `/resource trade executions <list|inspect|approve|retry>`。命令和服务都复核当前创始人身份，管理员标记不绕过创始人检查；retry 不补齐批准。查询只显示本国参与记录，显示冻结价格和数量，未知结果提示保留原编号。配套使用规则见 StarCore `docs/TRADE-EXECUTION-RECOVERY.md`。

## 保留边界

这不是国库和资源数据库的共同事务；它依靠持久意图与原编号回执恢复。内存成功事件是尽力通知，不能宣称恰好一次；Chronicle 依据持久资源交付回执写历史，不虚构个人贡献。无持久国库权威的原生服务不可执行付费贸易。非原生 ResourceService 的旧 boolean 兼容路径仍不具备本协议保证，新编号 API 不对它提供持久执行。

执行账本和国库回执仍常驻、全量编码，巨大历史的恢复和长期容量未完成验证。旧直接配额 API 没有调用方编号，未知后需恢复权威再查询，不可盲目重用。读取仍是本实例已提交快照，不构成多实例线性一致保证。MySQL、当前构件 Minecraft／全栈 Folia、第三方实际组合与长期负载继续待办，十阶段尚未全部完成。
