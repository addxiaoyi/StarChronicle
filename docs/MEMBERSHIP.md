# 成员资格复核与退出

玩家可从个人剧情或国家议事界面的「成员资格与退出」进入，也可使用：

| 命令 | 行为 |
| --- | --- |
| `/chronicle membership <实例ID>` | 查看自己的成员状态及复核入口 |
| `/chronicle reviews` | 查看最近 50 条成员状态 |
| `/chronicle revalidate <实例ID>` 或 `review <实例ID>` | 重新核验原成员资格 |
| `/chronicle leave <实例ID> [当前节点ID]` | 显式退出活动阶段；提供节点时拒绝过期界面 |
| `/chronicle join <实例ID>` | 满足条件后显式重新加入 |

公开 `ChronicleService` 提供对应的 `memberReview`、`memberReviews`、`revalidateMember` 与 `exitMember` 异步方法。服务在玩家实体线程重新读取身份和 `starchronicle.use` 权限，然后在状态工作线程处理数据库。原生成员复核在 StarCore NationModule 的成员变更锁内重新检查 `nationOf` 和国家存续；普通成员不需要国家持有人身份，管理员权限或称号也不能替代原生资格。独立模式只允许无国家成员的本地复核。

观察到换国或原国家从完整原生国家快照中消失后，成员变为 `PENDING`。当前个人计票会失效，历史选择日志保持原样；回到原国家不会自动解除待复核状态。显式复核还要求当前身份满足已固定剧情的前置条件及节点权限。复核不会重放进入节点时的奖励，也不会重新绑定任务回执。

退出仅作用于未完成实例；三参 API 校验当前节点令牌，两参兼容 API 退出处理时的活动阶段。退出会移除活动成员和当前个人票，保留已发生的历史选择、原生任务及奖励回执。后台轮询、重连和重启不会自动加回已退出玩家。公开插件的重新加入要求恢复原成员国籍并通过当前原生权威检查；个人剧情只允许原玩家，国家剧情还要求当前国家与实例范围一致。旧嵌入式 RuleEngine 构造器保留可信调用方已授权上下文、显式新成员决定的兼容语义，不能接收玩家自填身份；生产插件使用带 MemberAuthority 的构造器。

国家票属于国家席位。个人退出或成员换国不撤回整个国家的票，当前原生持有人可使用既有带修订号的国家撤票流程；已冻结决议保持不变。已完成实例的成员快照不能通过退出改写。

`story_member_reviews` 保存当前状态，`story_member_review_log` 追加保存本次升级之后的真实转换。重复观察相同状态不会持续追加日志；不会补造旧版本没有记录的转换。历史表与状态表同事务更新。任务历史兼容上游旧审核行与本分支追加退出日志；缺少全部原成员证明时仍拒绝恢复。

验证入口：`MemberReviewFlowTest` 覆盖真实 SQLite 重启、自动补入隔离、旧票失效、显式复核、权限变化、节点过期及完成历史保护；`NationalServicesTest`、`NationalCommandsTest` 和 `StarCoreNationalVoteAuthorityTest` 覆盖公开流程、实体线程快照及原生锁边界。实际构建与实服结果以当前续接报告为准。
