# 库存与普通交易快照完整性

2026-11-26，续接两库 `codex/plugin-all-stages-20261125`。原生旧快照解析会跳过错误库存或交易行、保留重复项中的第一条，并忽略资源列表中的非法部分。若直接把该结果当作权威恢复，下一次保存可能丢掉原库存或重试凭据。本轮在建立资源权威及提交异常对账之前增加库存／普通交易专用校验。

校验检查行数、连续且规范的索引、允许字段、必需字段、规范国家 UUID、已知资源、正整数数量、唯一国家＋资源和唯一交易编号。交易操作／分类、原时间和全部资源明细必须完整有效；不能保留一部分资源、丢掉另一部分。缺失计数却存在行、未知字段及超长描述也会拒绝。计数先与实际字段量核对，再读取逐行数据，损坏的巨量行数不会驱动巨量空循环。

校验失败时保留存储原值，关闭资源权威和全部库存写入，回执查询不能报告“没有执行”。启动不会把残缺解析结果写回；提交异常对账遇到非法字段也保持隔离，恢复存储后需重新启动。通用历史 decoder 的容错入口仍保留，权威模块在调用它之前已完成库存／交易检查。旧合法回执可缺少 description，并保留原编号和毫秒时间；空旧库存也继续支持初始化。

SQL 的旧文件迁移核对还可能更早调用通用 decoder，因此七类集合声明计数另有输入量上限检查；正常直接属性不构造额外键集合，继承属性按完整属性名集合核对。超大计数在这一更早的存储检查点会抛出恢复错误，不能使模块建立权威，也不驱动数十亿次循环。此上限不等于贸易协议等其他集合的逐字段严格校验。

本轮范围仅为库存和普通交易，不将其扩展称为贸易协议、路线、禁运或配额所有字段都已严格校验。它也不检测合法格式但内容被替换的任意篡改；完整性哈希／外部可信签名和多写入者一致性是独立约束。原生产／工厂日志验证继续执行，历史奖励和重试凭据不删除。
