# 资源旧文件首次导入校验

2026-11-26，续接贸易恢复与锁顺序检查点。首次资源文件迁入 SQL 时，旧实现先写状态、回执及迁移完成标记，再由 ResourceModule 或工厂恢复步骤发现坏库存／交易／贸易／工厂字段。模块虽已拒绝建立权威，SQL 仍可能留下无效的已迁移状态；仅修复原文件无法使下一次空库导入重新执行。

修复在首次导入空 SQL 的事务内、任何业务行或完成标记写入前校验旧库存、普通交易、贸易协议／路线／禁运／配额、资源域、生产日志及工厂运行凭据。工厂使用文件模式验证器核对原生产回执，不能将 SQL V3 属性文件当作完整归档导入。校验错误使事务回滚，原文件及数据库业务表保持原样；正常全量导入继续在同一事务提交。

此检查仅在迁移标记尚不存在且 SQL 状态为空、确实要导入全部文件时执行。已有 SQL 状态时继续只补迁交付回执，不对不会导入的旧库存应用新校验。迁移完成后的库存／配额等可变状态可以合法区别于保留旧文件；不能逐字段等同后误拒绝正常业务。保留旧文件后续被改写的认证、其所有字段与已迁移来源的映射仍待独立处理。本轮不宣称解决任意格式正确的篡改或多写入者一致性；旧版本已留下的无效 SQL 迁移仍需依据原始证据修复，不自动覆盖。

## 验证

新增 SQLite/H2 用例分别注入损坏库存、回执、四种贸易集合、工厂指纹、工厂与原回执不符、非法资源域及巨量计数；要求拒绝导入、五张业务／迁移表保持空、原文件保持原值。修复同一源对象后使用同一存储导入，确认库存、原支付回执、完整贸易字段及三项生产回执保留。另验证迁移后正常库存变化不会被保留旧文件覆盖或误拒绝。
