# SQL 国库完整凭据归档

2026-11-26 源码检查点。国库此前每次支出、入账、转账或退款都复制、排序并重写全部历史凭据。有持久权威域的 SQL 国库现在把三类凭据移入完整追加归档，活动快照只保留余额、权威域和归档头；已提交凭据不再常驻内存，原编号查询、去重和恢复继续有效。

首次业务保存与余额及 SQL 修订号同事务迁移。支出退款追加一条新凭据，原支出描述、分类、金额和时间不改写；若首次迁移由退款触发，也先保留旧支出再追加退款。旧文件本身保持。类别和编号共同确定身份，保留原有类别内去重；同一编号的冻结条款不能覆盖，已退款不能改回未退款。

归档行携带权威域、规范编码、连续序号与摘要链。文本按 UTF-8/Base64 保存，包含中文、换行及等号的旧描述保持完整；MySQL 建表采用 LONGTEXT 容纳编码后增长，当前没有 MySQL 实跑认证。启动和变更刷新最多 256 条一批核验全部历史。点查核对所读行、相邻摘要及退款来源，修订号变化先恢复数据库状态；原编号已提交返回已应用，否则拒绝供调用方按原编号重试。查询与写入沿用同一模块监视器，保存报错后核对原凭据，无法确认时保留原编号并隔离。

## 冻结旧数据与最终构件

旧 JAR 生成每类 500 条、共 1,500 条历史凭据，包括已退款和未退款支出、中文和换行描述。新旧构件用相同真实 SQLite 数据与文件在 96 MiB 堆下恢复、保存及重复保存 20 次，新构件再以 48 MiB 堆独立重启。按原编号重放收入和转账不会再次改余额。
