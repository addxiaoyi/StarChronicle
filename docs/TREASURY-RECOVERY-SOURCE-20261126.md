# 国库提交、回执与隔离恢复

2026-11-26，跨服务贸易恢复的国库前置检查点。原生 TreasuryModule 先前在保存异常后可能回滚内存并返回 REJECTED，即使资金已经提交；普通文件异常不触发完整重读，重读失败也未保持隔离。回执和余额查询还可能读到提交中的内存状态。

支出、入账、转账和退款现在在保存异常后核对完整持久快照。原编号回执匹配则确认已提交；无法读取、数据损坏或存储域改变时抛出携带原编号的 TreasuryTransactionUncertainException，隔离余额／回执读取及后续写入。连接恢复或定时刷新不自动解除隔离，关闭时不会用旧内存覆盖真实提交。恢复原存储并重新加载模块后，再查询／重试同一编号。

旧布尔存取款也生成内部支出／入账凭据，与余额同次保存，避免仅凭余额差推断某次操作是否提交。玩家存款使用与结果 UUID 对应的固定国库入账编号；国库结果未知时不立即向玩家退款，而在可用的退款账本中保留不自动重试的人工核对条目。个人经济服务仍不与国库共同提交。

余额、三类回执及存储域查询与写入共享监视器，等待提交及完整恢复。加载、恢复、刷新和首次旧文件导入 SQL 在兼容解码前验证计数、索引、重复身份、字段、金额、UUID、类别、时间和布尔值；损坏来源不被当成空国库。保留旧可选描述、未退款默认值与继承属性，非空无域旧数据不自动获得新权威。

## 后续边界

国库回执仍全量保存和常驻，布尔接口新增的内部凭据会增长；不可删除重试凭据解决容量。读取是本实例的已提交快照，不是跨实例线性一致读取。未建立持久域的模块与第三方 provider 仍不构成原生权威。配套使用规则见 StarCore docs/TREASURY-RECOVERY.md。

贸易协议仍需持久执行编号、冻结条款、国库／资源恢复状态、持久配额预留及一次性路线统计。玩家个人经济与国库也没有共同事务。MySQL、Folia 全栈、第三方实际组合、长期负载及当前构件实服验收继续待办，十阶段未全部完成。
