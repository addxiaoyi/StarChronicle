# 好友请求方向、持久事务与文件模式关系适配

旧好友服务把同一个请求写入双方集合，因此重复发送同方向请求也能自行批准；接受请求会先删除请求，再检查好友上限，数据库的双向关系与请求清理又分属多次吞错写入。旧关系适配器用反射修改私有集合，连零／负数强度变更也会添加或删除好友。

本批把内部请求统一为“接收者 → 发送者”，同方向重复发送返回 false，只有真正收到的反向请求才能互相接受；检查双方上限后才消费请求。公开 `getFriendRequests` 保留旧待处理联系人并集契约，新增收到／发出视图；命令收件箱、GUI 数量及单玩家导出改用收到视图。好友操作由同一服务锁串行，两个并发接受不能挤占同一个最后名额。

SQL 双向好友、两方向请求清理在同一事务；拉黑的好友移除、请求清理与黑名单也在同一事务。先确认提交再发布内存；拒绝、移除、取消拉黑和玩家清理不再吞错。提交响应丢失／回滚失败会阻止后续写入和周期保存，完整重载成功后才解除。已确认回滚的普通写入失败保留请求并允许重试。严格恢复使用一份连接上的数据库快照，解析失败不发布部分内存；显式配置的数据库不可用时不另建 YAML 权威。兼容 SQLite 旧 receiver／status／expires 字段；已处理／过期请求不提供接受资格。非 SQLite 列检测改用 JDBC 元数据，实际 MySQL 未运行。

YAML 模式把好友、收到请求、未确定方向的旧请求、黑名单与在线状态写入同一 schema 2 文件，临时文件 force 后原子替换。写入失败恢复原内存并隔离后续变更。旧无版本 YAML 的全部请求都保留为待核对记录，不猜测发送方向，不作为同意；第一次保存保留原字节 SHA 命名备份，重新发起才形成新方向。无效 UUID、未来格式、错误字段类型和未知字段会使恢复失败，原文件保留。文件原子移动保证不等于断电／文件系统持久性认证。

单玩家导出标记 `incoming-v2` 并保留旧待核对记录；导入先验证玩家身份、格式和全部 UUID，再一次提交好友状态，坏尾部不会留下部分好友。未标方向的旧单玩家导出只进入待核对集合；SQL 模式无法保存此类未确定记录时明确拒绝。全量跨好友／公会／派对导入仍待后续修复。

文件模式关系适配器不再反射或吞异常。它明确是好友 50／陌生人 0 的投影，不编造互动时间；达到好友阈值通过请求服务取得同意，零变更不修改、负变更拒绝，轻微降低不直接删好友，不支持的关系类型明确报错。集合不可变、并列最好友按 UUID 稳定选择，停用后拒绝变更。该投影没有可累计的完整关系强度或敌人／恋人持久模型。

## 仍待完成的源码与实服边界

FriendCommand 的异步 I/O、跨玩家名字和布尔结果反馈、父社交 GUI、全量导入导出的路径与多服务提交、社交周期保存、活动／联盟／文化和其余阶段仍有待办。本批数据库事务只有本服务拥有状态的运行模型；不声明多进程同时写同一数据库、在线外部编辑或旧 JAR 降级写入安全。YAML 每次写完整快照，SQL 显式完整保存仍遍历内存图，规模和长期负载需单独核验。未知提交后内存保留先前快照供核对，不能把它当作已确认的新数据库状态。

只做源码、单元测试与离线副本验证，没有启动 Minecraft／Paper／Folia，没有部署或合并主分支。MySQL、真实多人／重启、第三方组合、在线热卸载、长期负载和全栈 Folia 仍待实际验收；十阶段未完成，旧构件的实服证据不转用于当前 JAR。
