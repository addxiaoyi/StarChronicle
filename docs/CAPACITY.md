# 容量与维护（schema 8）

schema 8 新增 `instance_members` 派生索引及写入触发器，成员加入／退出与剧情正文在同一 SQLite 事务提交。升级逐条读取原实例，保留原 JSON、时间、选择、奖励、任务和来源回执；不会用索引代替正文成员检查或原生国家授权。缺失派生表或同步触发器时，下次打开会从正文重建；手工修改数据库不属于受支持的运维操作。

V1／V2 的选择迁移只在 SQLite 临时表保存 ID、秒、纳秒和 UTF-16 排序键，逐条验证、逐条导入。原先的真实时间排序、相同时间的 Java ID 顺序、未知旧投票时间和整次升级回滚保持不变。临时存储使用磁盘和 2 MiB 页缓存；迁移需要足够的数据库、WAL 与临时文件空间。每条记录自身大小仍决定单条解码的内存下限。

旧定义快照及 V1→V2 规范关联逐条迁移，原始定义字节与哈希保持不变。规则加载逐条校验全部归档证据，只暂存当前剧情及其条件直接引用的精确旧版本；退休剧情自身的依赖不会递归启用。归档写入后仍完整复核，提交后运行时仅持有当前启用定义。未引用证据的损坏仍会拒绝加载，不跳过哈希、规范格式或升级关联校验。

公开 `DefinitionCatalog.read` 仍返回全部定义和变体，不改变完整目录接口。大量当前定义、被引用版本的大量冲突变体、单条超大定义及主动使用完整目录时仍需要相应内存。加载仍多次线性扫描全部证据，CPU 与磁盘读取成本随历史增长；本改动不承诺无限容量，也不删除旧定义。

## 查询接口

- `instances(playerId)` 保留完整结果的兼容语义，按成员索引查询，不解析无关实例。
- `instances(playerId,page,size)` 只解码当前页，page 从 0 开始、最大 1,000,000，size 为 1–100。深页仍有 OFFSET 成本。
- `instance(playerId,instanceId)` 定点读取并检查正文成员资格；不存在或非成员返回空。任务、国家议事与成员详情界面使用此接口。
- `storyPage(playerId,afterId,size)` 返回本人历史及当前可见的共享活动剧情。首次 afterId 为 null，每次最多返回 100 条、检查 256 个候选。返回的 `nextCursor` 为 null 才表示结束；空页可能仍有下一页。内置剧情列表使用此接口。

游标按数据库 ID 顺序继续；它不授予权限，也不是固定时点快照。翻页期间的创建、完成、退国和退出仍按下一次采集的身份重新判断，回翻会重新查询。动作继续核验当前节点、成员、权限、任务、国家席位和原生权威。新增默认方法保持既有第三方接口实现可加载；默认成员分页／单项查询会委托旧全量方法，实际本插件实现使用数据库筛选。

成员观察及活动实例补入改为每批 64 个快照，不持有整个活动实例集合；它们仍处理全部适用实例，耗时与总工作量相关。权限采集只保留去重权限字符串。`activeInstances()`、旧全量查询和完整定义目录仍是有成本的管理接口。分页不限制规则计算、历史条件子查询或首次触发恢复的总耗时。

规则条件及 NPC 事件反应仅查询条件引用的历史类型；普通条件不会读取历史计数。世界计数使用 `history_type(type,id)` 派生索引，每批最多绑定 256 个类型，国家／玩家计数继续关联真实主体索引。在调用方同一事务内直接读取，不缓存跨事务结果。索引会在打开现有 schema 8 库时补建，不改写原事件或提升 schema 版本。

旧 `history.TYPE` 在缺少事件时仍不存在；明确的 `chronicle.history.world/nation/player.TYPE` 仅在主体已知时返回零。未知玩家或空国家仍是未知。公开完整历史投影和 NPC 对话视图保留完整内容，以支持无条件文本中的历史占位符。类型较多、单类历史较大、完整 NPC 视图和深页查询仍有相应读取成本。

## 备份与容量巡检

安装前先备份实际 `chronicle.db`。支持 Python 3 的管理机可执行：

```text
python tools/inspect-capacity.py /path/to/chronicle.db
python tools/inspect-capacity.py /path/to/chronicle.db --backup /path/to/new-backup.db
```

源数据库以只读方式打开。备份使用 SQLite backup API，包含已提交 WAL，拒绝覆盖已有路径，完成后检查完整性。默认读／备份超时为 120 秒，可用 `--timeout` 调整。失败的新备份会保留并明确标记失败，不应部署。活跃数据库不要只复制主 `.db` 文件；恢复时停服，保留原库及其 WAL／SHM，使用已验证备份建立独立恢复目录后检查，再启动插件。

巡检输出已分配和可复用空间、主要表行数、outbox 状态及触发受众。空闲页可由 SQLite 重用；本工具不执行 VACUUM、删除、清账或重新发奖。

`players:*`、`nations:*` 与 `nation-players:<id>` 种子供未来玩家／国民领取，不能因当前玩家已消费就删除。稳定来源回执、outbox、choice、贡献、任务轮次和消费去重键均属于长期证据；不得用 TTL 删除来控制磁盘占用。达到容量预警后，应先扩容、备份并分析实际主要表，再设计保留原去重与可追溯性的独立归档方案。当前没有自动清理这些证据的策略。

## 可复现实测

`tools/run-capacity-contract.py` 接受冻结的 schema 7 旧 JAR、当前 JAR、JDK 与新输出目录。默认分别建立 15,000 实例的真实 schema 7 库和按原始 DDL 建立的 V2 库，在串行 `-Xmx64m` JVM 中升级、查询、再启动，并独立核验原表逐行摘要、成员覆盖、旧选择排序与数据库完整性。保留旧构件在同一小堆下的迁移 OOM 作为对照；该旧失败不算当前构件通过。

`tools/run-definition-capacity.py` 接受 `--previous`、`--chronicle`、`--java-home`、`--output`，默认生成 6,000 个历史版本（每个四节点、每节点 4,096 字符，混合 V1／V2 证据）。在独立的串行 64 MiB 堆进程中比较旧构件与当前构件的加载、纯校验、重载和再次启动，逐表核验原始数据与数据库完整性。工具保留实际旧构件结果；只有日志确实记录 Java 堆 OOM 时才将其标记为旧容量失败，不将一般进程失败当作预期结果。

此测试只覆盖隔离 SQLite 与 JVM。64 MiB 是 Java 最大堆，不是进程总内存，也不是生产服务器配置建议。实际报告、构件哈希、规模、耗时及未验证项目单独记录；它不能替代当前构件的 Paper／Folia 或第三方组合验收。
