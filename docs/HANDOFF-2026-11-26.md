## 新设备构建与复验

Java 21、Python 3.11+、Node 22 与 Maven Wrapper。依赖首次获取时不要使用 Maven `-o`；Windows 使用 `mvnw.cmd` 并设置相同 JVM 参数。

```bash
env MAVEN_OPTS='-Xmx768m -XX:+UseSerialGC' ./mvnw -B -ntp verify
npm install --prefix run/epic-client mineflayer@4.39.0
export EPIC_MINEFLAYER_MODULE="$PWD/run/epic-client/node_modules/mineflayer"
python3 tools/prepare-epic-paper.py prepare --route DUNGEON --ledgers --attempt NEW-ATTEMPT --port 29651 --starcore /path/to/starcore/target/starcore-1.0.0.jar --runtime /path/to/initialized-paper
python3 tools/prepare-epic-paper.py compile --run run/PREPARED-DIRECTORY --java-home /path/to/java21
python3 tools/epic-paper-session.py --run run/PREPARED-DIRECTORY --java-home /path/to/java21 --node /path/to/node --boot 1 --scenario first
python3 tools/epic-paper-session.py --run run/PREPARED-DIRECTORY --java-home /path/to/java21 --node /path/to/node --boot 2 --scenario second
python3 tools/epic-paper-session.py --run run/PREPARED-DIRECTORY --java-home /path/to/java21 --node /path/to/node --boot 3 --scenario third
python3 tools/inspect-epic-paper.py run/PREPARED-DIRECTORY
STARCHRONICLE_EPIC_RUN=run/PREPARED-DIRECTORY python3 -m unittest discover -s tools -p test_epic_acceptance.py -v
```

`--runtime` 是已有 `paper.jar`、`cache/`、`libraries/` 的 Paper 1.21.11 目录。WAR 使用独立 attempt、世界和端口重复；失败 boot 不可覆盖重写为通过。Mineflayer 必须按 1.21.11 发送 `player_loaded`；本机 4.39.0 的 `health.js` 已具备该握手。若新设备实际不能进入世界，应记录真实启动失败并核对客户端版本，不能手填制作事件。

归档工具新增 `--build-log` 和 `--additional-evidence`，可收集本轮日志及旧库恢复目录。使用唯一 label 保留轮次，冻结原生 JAR 以 `--starcore-jar` 指定，并用 `--native-artifact-commit c5593e0d` 校验生产源码。本轮[清单](verification/national-epic-ledgers-linux-20261126-summary.json)和[证据包](verification/national-epic-ledgers-linux-20261126-evidence.zip)已校验 284 个成员哈希、ZIP 完整性和密钥脱敏。
